# SEO, Open Graph & Google Images — Runbook

Everything that ships the site's identity, share cards, and search signals.
This file is the single source of truth for what each SEO piece does, where
it lives, and which commands to run.

Brand pattern: **Aakash Sethi (Founder) → Tnufa AI (Product)** — same shape as
OpenAI→ChatGPT, Anthropic→Claude, Vercel→Next.js. Person schema owns the
identity, product schema hangs off the person.

---

## 1 · What each file does

| File | Role |
| --- | --- |
| `_config.yml` | Site title, description, `default_og_image`, `og_site_name`, plugin list, front-matter defaults for posts. |
| `Gemfile` | Adds `jekyll-seo-tag` and `jekyll-sitemap` gems. |
| `_layouts/single.html` | Post template. Per-post OG image with fallback, BlogPosting + BreadcrumbList JSON-LD, in-page cover `<figure>` for Google Images, lazy Giscus, `site.time` footer year. |
| `index.html` | Homepage. Person + ProfessionalService + FAQPage + WebSite schema. `PriceSpecification` for the $299 initial consultation. React scripts `defer`. `<noscript>` fallback. |
| `blog/index.html` | Blog hub. OG + Blog + BreadcrumbList schema. Posts server-rendered as static `<a class="post-row">` so bots see titles in initial HTML. JS enhances search/filter. |
| `consulting.html` | Pricing page (`/consulting/`). 4 tiers visible: intro $299, Starter $2.5–3.5k/qtr, Growth $5–7.5k/qtr, Enterprise $10–15k/qtr. Full `Service` + multi-`Offer` JSON-LD with `PriceSpecification` per tier (uses `minPrice`/`maxPrice` for ranges). Post topbar & CTA card link here. Testimonials TODO block. |
| `privacy.html` | Minimal OG (og:type=website), favicons, RSS discovery. |
| `sitemap.xml` | **Do not commit a hand-written one.** `jekyll-sitemap` generates it at build time. |
| `sitemap-images.xml` | Iterates posts with `cover_image` and emits `<image:image>` entries (Google Image sitemap 1.1 spec). Home + `/blog/` are hard-coded. |
| `robots.txt` | Allows all reputable crawlers including AI training bots (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot, Applebot-Extended). Points at both sitemaps. |
| `manifest.webmanifest` | PWA manifest. Name = "Aakash Sethi \| Tnufa AI", `theme_color = #0A0B0D`. |
| `favicon.ico` | Multi-res (16/24/32/48/64) generated from `assets/monogram.svg`. |
| `assets/icons/` | `icon-32.png`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` — rasterized from the monogram. |
| `assets/og/home-og.jpg` | The 1200×630 share card every OG tag points at. Generated by `generate_site_images.py --og-card`. |
| `generate_site_images.py` | Local dev tool (gitignored). Portfolio images + `--og-card` mode that generates the background via fal.ai and overlays copy with Pillow. |
| `scripts/wire_post_images.py` | Matches `assets/posts/*.png` to `_posts/*.md` slugs. Adds `cover_image` + width/height + alt to front matter. Idempotent — skips posts that already have it. |

## 2 · Front-matter contract for posts

Every `_posts/*.md` gets these fields (either hand-set, or via
`scripts/wire_post_images.py`):

```yaml
---
layout: single
title: "Your post title"
date: 2026-07-06
categories: ["AI Engineering"]
tags: [foo, bar]
excerpt: "One-sentence summary used in search results and social previews."
cover_image: /assets/posts/2026-07-06-your-post-slug.png
cover_image_alt: "Your post title — cover art"
cover_image_width: 1200
cover_image_height: 630
---
```

Posts without `cover_image` fall back to `site.default_og_image`
(`/assets/og/home-og.jpg`). The layout gracefully skips the in-page `<figure>`
when `cover_image` is absent.

## 3 · Commands — day to day

### Add a new post
```bash
# 1. Write your markdown under _posts/YYYY-MM-DD-slug.md
# 2. Drop the cover image at assets/posts/YYYY-MM-DD-slug.png (1200x630 recommended)
# 3. Wire the front matter (idempotent — safe to re-run any time)
python3 scripts/wire_post_images.py --dry-run   # preview
python3 scripts/wire_post_images.py             # apply
# 4. Build and eyeball
bundle exec jekyll serve --livereload
```

### Regenerate the OG share card
```bash
# Requires FAL_KEY in ../LinkedInMarketing/.env
python3 generate_site_images.py --og-card           # skips if file exists
python3 generate_site_images.py --og-card --force   # rebuild
```
Output: `assets/og/home-og.jpg`. Copy is baked into the script — edit the
overlay lines inside `build_og_card()` if you rebrand.

### Regenerate portfolio images (hero, about, work, thumb, LinkedIn bg)
```bash
python3 generate_site_images.py                     # incremental
python3 generate_site_images.py --force             # rebuild all
```

### Verify a Jekyll build locally
```bash
bundle exec jekyll build

# Sitemap should list every post + /blog/ + /privacy/
grep -c "<loc>" _site/sitemap.xml

# Image sitemap — one <image:image> per post with a cover image + 2 for home + 1 for /blog/
grep -c "<image:image>" _site/sitemap-images.xml

# Pick any rendered post and confirm the head has og:image with a resolvable URL
grep -E 'og:image|BlogPosting|BreadcrumbList' \
  "_site/ai engineering/2026/06/09/how-malicious-links-hijack-ai-assisted-workflows.html" | head -12

# Confirm blog index has server-rendered post anchors (not just JS)
grep -c 'class="post-row"' _site/blog/index.html
```

### Regenerate favicon set (only if the monogram changes)
```bash
mkdir -p assets/icons
rsvg-convert -w 32  -h 32  assets/monogram.svg -o assets/icons/icon-32.png
rsvg-convert -w 180 -h 180 assets/monogram.svg -o assets/icons/apple-touch-icon.png
rsvg-convert -w 192 -h 192 assets/monogram.svg -o assets/icons/icon-192.png
rsvg-convert -w 512 -h 512 assets/monogram.svg -o assets/icons/icon-512.png
magick assets/icons/icon-32.png -define icon:auto-resize=16,24,32,48,64 favicon.ico
```

Requires Homebrew: `brew install librsvg imagemagick`.

## 5 · Schema.org map — what emits what

- **Homepage `index.html`** — 4 JSON-LD blocks:
  1. `Person` (`@id: /#person`) — the identity. Owns `founder` relation to Tnufa AI.
  2. `ProfessionalService` — offers & prices. Update `PriceSpecification` here when prices change.
  3. `FAQPage` — targets featured snippets. Edit the 5 Q/A pairs when messaging shifts.
  4. `WebSite` — hangs off Person.
- **Post `_layouts/single.html`** — 2 JSON-LD blocks per post:
  1. `BlogPosting` (`@id: <post-url>#article`) — declares `image`, `author`, `publisher`, `wordCount`, `articleSection`, `isPartOf` the Blog.
  2. `BreadcrumbList` — Home → Writing → Category → Post.
- **Blog `blog/index.html`** — 2 JSON-LD blocks:
  1. `Blog` (`@id: /blog/#blog`) — lists first 20 posts inline as `blogPost`.
  2. `BreadcrumbList` — Home → Writing.

All Person references use `@id: https://aakashsethi.github.io/#person` so
search engines merge the entity across pages.

## 6 · Merge / rebase runbook (concurrent commit conflicts)

When `git push` is rejected because remote has diverged:

```bash
git fetch origin main
git log --oneline HEAD..origin/main               # what the remote has
git diff --name-only HEAD...origin/main            # which files diverged
```

If SEO / identity files (`_config.yml`, `_layouts/single.html`, `index.html`,
`sitemap-images.xml`, `robots.txt`, `Gemfile`) show up on both sides, do NOT
blind-rebase. Instead:

```bash
# 1. Fetch a snapshot of each conflicting file from remote for side-by-side comparison
mkdir -p /tmp/remote-snapshot
for f in _config.yml _layouts/single.html index.html sitemap-images.xml robots.txt Gemfile; do
  git show "origin/main:$f" > "/tmp/remote-snapshot/$(echo "$f" | tr / _)" 2>/dev/null
done

# 2. Diff each file's local vs remote version
diff -u /tmp/remote-snapshot/_config.yml _config.yml | head -80
diff -u /tmp/remote-snapshot/_layouts_single.html _layouts/single.html | head -120
# ...etc

# 3. Decide which side wins per hunk, or hand-merge to a superset

# 4. Rebase (starts the conflict-resolution loop)
git rebase origin/main
# For each conflict:
#   - Open the file, resolve markers
#   - git add <file>
#   - git rebase --continue
# If you get lost, git rebase --abort restores state.

# 5. Verify build + rendered head tags before pushing
bundle exec jekyll build
grep -c "<loc>" _site/sitemap.xml
git push origin main
```

**Never** force-push to `main` without explicit approval — `.github/workflows/`
on the remote may be running scheduled commits (e.g., weekly-blog.yml) whose
history you'd lose.

Every SEO change is in one of six focused commits:

```
d843b89  OG card asset (regenerate with the generator)
0582d5e  favicon set + PWA manifest + OG generator
d74dba0  cover_image front matter across 19 posts
b227ec2  per-post OG + BreadcrumbList + in-page cover
62c759c  homepage + blog index + privacy OG + $299 schema + founder branding
6a3f724  jekyll-seo-tag + jekyll-sitemap + robots.txt AI-crawler policy
```

Revert any one with `git revert <sha>`. They're ordered so reverting later
commits doesn't break earlier ones.

## 8 · Pricing (public tiers)

Visible on `/consulting/` and echoed in JSON-LD `ProfessionalService.hasOfferCatalog`
on `/` and `Service.offers` on `/consulting/`.

| Tier | Price | Cadence | Slug |
| --- | --- | --- | --- |
| Initial Consultation | $299 | one-time · 60 min | `#intro` |
| Starter AI Advisory | $2,500 – $3,500 | per quarter | `#starter` |
| Growth AI Retainer | $5,000 – $7,500 | per quarter | `#growth` |
| Enterprise AI Optimization | $10,000 – $15,000 | per quarter | `#enterprise` |

Ranges use `PriceSpecification.minPrice` + `maxPrice` + `unitText: "quarter"`
so Google surfaces the range cleanly in rich results. When rates change,
update BOTH `consulting.html` (visible + JSON-LD) AND `index.html`
(ProfessionalService OfferCatalog) — schema must mirror visible content.
